### [XNU 内核移植至红米 Note 10 Pro 并启动 iOS 16](https://www.reddit.com/r/hackintosh/comments/1x95qq0/ios_16716_booting_on_a_snapdragon_732g_redmi_note/?sort=new) ⭐️ 8.0/10

开发者将苹果开源的 XNU 内核移植到红米 Note 10 Pro（骁龙 732G），并运行未经修改的 iPhone X 版 iOS 16.7.16 用户空间。据项目信息，该系统已于 10 月 18 日启动至 iOS 主屏，触摸和实体按键可用，代码已在 GitHub 开源。目前画面完全由 CPU 渲染，约为 20–30 帧/秒，尚无 GPU 驱动，Wi-Fi 和相机等功能暂不可用。

telegram · zaihuapd · 10月19日 06:30

**「背景」** XNU 是苹果开源的混合内核，源自 Mach 与 BSD 组件，是 iOS 和 macOS 的内核基础。把 iOS 用户空间运行在非苹果硬件上，除了启动内核，还需要为具体 SoC 的 GPU、Wi-Fi 等外设补齐驱动；这也解释了当前移植为何只能靠 CPU 渲染，并且缺少无线功能。

**「实际影响」** 这一移植目前更适合内核、驱动和逆向工程研究：开源代码可供其他开发者检查 XNU 在非苹果硬件上的启动与输入路径，但缺少 GPU、Wi-Fi 和相机支持，意味着它还不能作为日常可用系统。

### [Wine 移植至 OpenBSD，改动标记为 OpenBSD 专属](https://marc.info/?l=openbsd-ports&amp;m=179236125692175) ⭐️ 7.0/10

根据 OpenBSD ports 邮件列表的消息，Wine 已被移植到 OpenBSD，使这一 Windows 应用兼容层能够在该系统上构建运行；材料中没有给出具体版本号、可用功能范围或正式发布形式。评论中引用的后续邮件称，为 OpenBSD 所做的改动被统一标记为仅适用于 OpenBSD 平台，移植者认为这些改动不太可能大量合并回上游。因此这目前是一项由社区维护的平台移植，而非已进入 Wine 上游的通用支持。

hackernews · iamnothere · 10月19日 13:35 · [社区讨论](https://news.ycombinator.com/item?id=50152307)

**「背景」** Wine 是在非 Windows 系统上实现 Windows API 的兼容层；要把这类软件引入 OpenBSD，需要通过该系统的 ports 机制提交构建规则和补丁。据 OpenNet 报道，OpenBSD 禁止用户态设置 gsbase 寄存器，而 Windows 程序常用该寄存器访问线程局部存储，这被认为是运行 Wine 的主要障碍。

**「影响」** 对 OpenBSD 用户而言，这意味着可以尝试在本地运行依赖 Wine 的 Windows 程序；但由于相关修改被标记为 OpenBSD 专属且预计难以回流上游，用户需要跟随该移植自身的更新节奏，兼容性改进与修复也取决于移植维护者而非 Wine 上游。

**「社区讨论」** 有评论者对这一移植表示欢迎，认为在 OpenBSD 逐渐被视为“slopcode”避风港的当下尤显及时，这属于个人观点而非既成事实。也有评论者打趣移植者的姓氏 Frohwein 在德语中意为“快乐的葡萄酒”，以及该项目本可以命名为“Port”。

### [Mistral 宣布 Timestral 时间序列基础模型系列](https://mistral.ai/news/timestral/) ⭐️ 7.0/10

Mistral 宣布推出 Timestral，一个面向时间序列预测的基础模型系列，面向需要处理预测任务的开发者与数据团队。当前材料只确认了这一定位，没有给出模型版本、参数规模、训练数据、许可方式、发布时间、价格或基准结果，因此尚不能判断其相对专用预测模型的实际表现，也不能确认它已普遍可用。

hackernews · groar · 10月19日 09:59 · [社区讨论](https://news.ycombinator.com/item?id=50150434)

**「背景」** 时间序列基础模型（TSFM）指的是在大量不同序列上预训练、可直接用于零样本预测的通用模型，其思路是用一个模型替代为每条序列单独训练的统计或机器学习模型。Mistral 的 Timestral 即以这一形态发布，包含 5M、28M、123M 和 209M 四种参数规模的检查点，并已在 Hugging Face 上提供下载，可本地安装运行。Mistral 方面强调时间序列是企业最常见的数据类型之一，从传感器遥测到可观测性指标，其预测结果用于容量规划、能源、供应链、风险与维护等决策。

**「对多序列预测团队的影响」** 对需要同时预测成千上万条序列的团队来说，Timestral 提供的是一条免训练的零样本路径：不必为每条序列单独建模，只需按接口传入历史窗口、过去与已知未来协变量，再读取概率分位数输出。落地前需核对两点兼容性：上下文最长支持 32K 个时间步，且该系列覆盖 5M 至 209M 参数的多档模型，小模型与大模型在精度和 CPU 延迟上的取舍需自行验证。Mistral 自报其在 GIFT-Eval、TIME 和 fev-bench 上位居预训练与零样本模型首位，这属于厂商声明，仍应以自有数据复测为准。

**「社区讨论」** 评论者对“把所有时间序列归入一个通用模型”是否合理存在分歧：有人指出，面对上万条序列时，逐条训练专用模型会因历史数据不足而受限，而单一通用模型又要处理不同序列间的量纲和分布差异。也有人把它类比为 ChatGPT 式的泛化能力，期待可扩展或易微调带来零样本、少样本预测，但同时怀疑大型量化机构是否早已在内部实现类似能力。
